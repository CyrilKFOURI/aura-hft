# Technical Specification: NASDAQ OUCH 5.0 Order Entry Protocol

## 1. Role of the protocol
* OUCH is the proprietary, ultra-fast binary protocol used to send orders (buy/sell/cancel) directly into the NASDAQ matching engine.
* Unlike FIX (which is verbose, tag-delimited text), OUCH uses fixed-field binary messages to minimize processing latency in the exchange gateway.
* In an FPGA tick-to-trade architecture, the decision block triggers an output OUCH generator that builds the binary frame and sends it onto the optical cable within a few tens of nanoseconds.

---

## 2. Order entry message structure: "Enter Order"

| Offset | Field | Size | Type | Description |
| :--- | :--- | :--- | :--- | :--- |
| 0 | `Type` | 1 | Alpha (`'O'`) | Enter Order identifier |
| 1 | `UserRefNum` | 4 | Integer | Unique order identifier generated by the trader / FPGA |
| 5 | `Buy/Sell Indicator` | 1 | Alpha | `'B'` = Buy, `'S'` = Sell |
| 6 | `Shares` | 4 | Integer | Number of shares requested |
| 10 | `Stock` | 8 | Alpha | Stock symbol, space padded |
| 18 | `Price` | 4 | Integer | Limit price (fixed point, 4 decimals) |
| 22 | `Time In Force` | 4 | Integer | Validity period (e.g. Day, IOC - Immediate or Cancel) |
| 26 | `Firm` | 4 | Alpha | Member / broker identifier |
| 30 | `Display` | 1 | Alpha | `'Y'` = Displayed in the book, `'N'` = Hidden order |
| 31 | `Capacity` | 1 | Alpha | Agency, Principal, Risk |

---

## 3. Hardware generator implementation (egress path)
* **1-cycle generation:** As soon as the market condition (e.g. order book imbalance $OBI > \tau$) is validated by the strategy block:
  1. The registers holding the symbol, the computed price and the volume are multiplexed.
  2. `UserRefNum` is incremented by 1.
  3. The OUCH message is wrapped in the session header (SoupBinTCP) and the network header (IP/TCP/Ethernet).
  4. The 512/64-bit word is immediately pushed onto the MAC core's transmit AXI-Stream bus.
